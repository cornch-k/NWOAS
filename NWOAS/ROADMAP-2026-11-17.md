# NWOAS 남은 일 전체 로드맵 — 맥미니에서 Windows를 "네이티브"로 쓰기까지 (2026-11-17)

> 이 문서는 남은 일 전체를 한 번에 보는 총괄판입니다. 분야별 원문(근거 파일·줄 번호, 단계별 표)은 `research-20261117/roadmap/` 아래 다섯 문서에 있습니다(맨 끝 13장).
> 표기: **[사실]** = 코드·로그·실기기로 확인. **[가설]** = 확인하지 않은 추측. **빌드 성공은 동작이 아닙니다.** 모든 단계의 성공은 실기기 검증 결과로만 판단합니다.
> 이번 조사는 읽기와 웹 조사만 했습니다. 아무것도 빌드·실행하지 않았고, 맥미니도 건드리지 않았습니다.

## 0. 결론

**"네이티브"까지 남은 길은 크게 네 줄기입니다.**
1. **맥북 없이 켜기**
2. **하이퍼바이저가 CPU·SSD를 막고 있는 부분 풀기**
3. **장치 드라이버 채우기**(소리·와이파이는 승인 대기)
4. **게임·앱 호환**

이 가운데 **효과는 크고 일은 작은 것**이 하이퍼바이저 쪽에 몰려 있습니다. 그래서 이것부터 합니다.

이번 조사에서 새로 확인한 것 중 중요한 것(제가 코드를 직접 다시 열어 확인한 것은 ✔):

| # | 발견 | 사실/가설 | 영향 |
|---|---|---|---|
| 1 | ✔ Windows가 쉬려고 내는 대기 명령(WFI)을 하이퍼바이저가 붙잡은 뒤 **기다리지 않고 바로 다음 명령으로 넘깁니다**(`m1n1-gpu-hv2/src/hv.c:88`, `hv_exc.c` WFI 처리 끝 `elr += 4`). 참조 프로젝트는 같은 자리에서 실제로 잠듭니다 | 사실(코드) | 쉬는 동안에도 8개 코어가 계속 돎 → 전력·열·팬 [가설: 실측 없음] |
| 2 | ✔ 보조 CPU 7개도 하이퍼바이저 주기 작업을 **초당 5,000번** 돕니다. M1에는 ECV가 없어서 `hv_secondary_tick_interval = hv_tick_interval`이 됩니다(`hv.c:126-141`). 참조는 100번입니다 | 사실(코드) | 줄이면 하이퍼바이저 진입이 초당 약 3만 4천 번 줄어듭니다(계산) |

| 4 | ✔ **SSD 명령을 하이퍼바이저가 한 번에 하나씩만** 넣고 끝날 때까지 돌며 기다립니다. 태그 0번 하나만 쓰고(`nvme.c:217`), 문 두드리기 한 번에 1개, 나머지는 주기 작업마다 1개씩 처리합니다(`hv_vm.c:1600`, `:1743`) | 사실(코드) | 큰 파일 순서대로 읽기·쓰기는 9월에 이미 빠름. 앱 실행처럼 작은 조각을 동시에 많이 읽는 일이 느릴 것 [가설, 잰 적 없음] |
| 5 | ✔ Windows **"종료"가 실제로는 재시작**입니다. 재시작·종료 어느 쪽도 SSD 제어 칩을 정상 종료하지 않습니다(`hv_psci.c:1518-1541`) | 사실 | 끄기 기능 없음. SSD에 좋지 않음 |
| 6 | ✔ 시스템 공용 캐시(SLC)를 켜는 함수 `mcc_enable_cache()`는 리눅스식 부팅 경로(`kboot.c:2816`)에서만 불립니다. 하이퍼바이저 경로에서는 불리지 않습니다 | 사실(코드). 실제로 꺼져 있는지는 가설 | 참조 프로젝트는 켠 뒤 GPU 시험 점수 +8.5% |
| 7 | 지금 GPU 드라이버(2757판)에는 **ARM64용 사용자 드라이버만** 들어 있습니다. x64·x86 앱(Prism으로 도는 모든 프로그램, 롤 포함)은 GPU 가속을 못 받습니다 | 사실(패키지 내용, 에이전트 확인) | 일상 사용에서 가장 값어치가 큰 그래픽 작업 |
| 8 | **롤은 Riot 쪽 조건에 막혀 있습니다.** Riot 공식 사양에 ARM CPU는 "지원 안 함"입니다. ARM용 Vanguard는 발표만 있고 날짜가 없습니다. 나와도 "가상화 아래 실행 거부", 메모리 무결성(HVCI) 요구 때문에 우리 구조를 거부할 가능성이 높습니다 | 사실(Riot 문서) + 가설(우리 구조 거부) | 우리가 다 만들어도 Riot 출시 전에는 안 됨 |
| 9 | **화면 쪽 맥북 의존은 이미 없어졌습니다.** 13.5 펌웨어에서는 m1n1 C가 화면을 켜고 하이퍼바이저 C가 DCP를 넘겨받습니다. 11-15 조사의 "C로 Tahoe 화면" 단계는 필요 없습니다 | 사실(실행기·코드) | 맥북 없는 부팅이 한 덩어리 줄어듦 |
| 10 | 지금 스텁에 등록된 D4 m1n1은 **디스크에서 다음 파일을 읽는 기능이 빠진 빌드**입니다("Chainloading files not supported" 문자열). 그래서 맥북 없는 부팅에는 스텁 복구 화면(1TR)에 **한 번** 가야 합니다 | 사실 | 콘치님 손 1번(약 5분). 그 뒤로는 ESP 파일만 바꾸면 됨 |
| 11 | ✔ UEFI의 PCIe 64비트 주소 창(`PcdPciMmio64Base = 0x400000000`)이 Apple PCIe가 실제로 넘겨 주는 창(0x6A0000000~)과 다릅니다 | 사실(설정값과 장치 트리) | 이더넷 레지스터에 CPU가 닿지 못할 가능성 [가설, 근거 강함] |
| 12 | 내장 유선 랜 칩은 Broadcom BCM57762(PCI ID 14E4:1682)입니다. Windows ARM64용 드라이버는 찾지 못했습니다(드라이버 모음 사이트는 모두 x64) | 사실(칩) + 검색 범위 내 미발견 | 드라이버를 직접 만들어야 할 수 있음. 먼저 Windows 드라이버 저장소부터 확인 |
| 13 | 16 GiB 중 바로 되찾을 수 있는 것이 **약 536 MiB**입니다(UEFI가 Windows에서 감춘 일반 메모리). 맥북 연결용 메모리 약 896 MiB는 맥북 없는 부팅이 되면 되찾습니다 | 사실(부팅 로그) | RAM 여유 |
| 14 | USB-A 저장장치 **읽기** 손상은 이미 해결됐습니다(S236·S237, PCIe 브리지 주소 1 MiB를 RAM에서 뺌, 실기기 통과). 남은 것은 쓰기·꽂았다 뽑기 시험입니다 | 사실 | 옛 문서(`network.md`, `NWOAS_USBA_NEXT_STEPS.md`)의 "미해결"은 낡은 기록 |

**지금 바로 시작할 수 있고 콘치님 손이 재부팅 확인뿐인 일**은 1장 "1단계 묶음"입니다. 8개이고 모두 작은 일입니다.

## 1. 전체 순서 (앞 단계가 뒤 단계의 바탕)

원칙:
- **측정부터** 합니다. 고치기 전과 뒤를 같은 시험으로 잽니다. 지금 구성(g254L + S256)으로 잰 SSD 속도·하이퍼바이저 진입 횟수·온도·GPU 점수·부팅 시간은 하나도 없습니다.
- **한 번에 하나만** 바꿉니다. 새 하이퍼바이저는 매번 새 폴더에 빌드하고, 지금 구성(g254L + S256)은 되돌아갈 자리로 둡니다.
- **콘치님 손이 필요한 일은 몰아서** 합니다(1TR 두 번, 물리 조작).
- 서로 기다릴 필요 없는 줄기는 **동시에** 진행합니다(아래 "동시 진행" 칸).

| 단계 | 묶음 | 들어가는 일 | 크기 | 콘치님 손 | 동시 진행 |
|---|---|---|---|---|---|
| **0** | 기준 측정 | SSD 속도(순차·4 KiB 무작위·동시 명령 수별), 하이퍼바이저 진입 계수기, SMC 온도 읽기, GPU 점수, CPU 점수, 부팅 구간 시간, 현재 Windows RAM | 작음 | 없음 | 1단계 준비와 함께 |

## 2. 맥북 없이 켜기 (상세: `research-20261117/roadmap/standalone-boot.md`)

### 2.1 지금 맥북이 하는 일 (s256 실행기 기준으로 다시 확인)

### 2.2 단계

| 단계 | 할 일 | 검증 | 콘치님 손 | 되돌리기 | 크기 |
|---|---|---|---|---|---|
| 4-1 | 디스크에서 다음 파일을 읽는 작은 m1n1(CHAINLOADING=1, `chainload=<ESP GUID>;m1n1\boot.bin`)을 스텁에 등록합니다. 처음에는 ESP에 **D4를 그대로** 둡니다 → 맥북 개발 방식이 지금과 똑같이 돕니다 | 체인로드 줄 뒤에 D4 시작 줄이 한 번 더 찍히고, 실행기가 끝까지 가서 바탕화면 | **스텁 1TR 1번(약 5분)** | 같은 1TR에서 원래 `step2.sh` 다시 실행 | 작음 |
| 4-2 | ESP의 `boot.bin`을 우리 하이퍼바이저로 바꾸고 "맥북 3초 기다리는 창", `\m1n1\nowin` 파일이 있으면 늘 맥북 대기 규칙을 넣습니다 | 맥북 붙임 → 지금과 같음 | 없음 | ESP 파일을 D4로 | 작음 |

**콘치님 손 단계(1TR) 전에 반드시 할 것** — 11-16의 실수를 되풀이하지 않도록:
- 13.5 복구 환경에 실제로 있는 명령만 씁니다. 목록 `research-20261116/C4-recovery-13.5-commands.txt`에 따르면 `diskutil`, `mount_msdos`, `md5`, `stat`, `sh`, `bputil`, `kmutil`, `bless`, `reboot`, `shutdown`은 있고 **`shasum`은 없습니다**. 이 목록은 디스크 이미지에서 뽑은 것이고, 켜진 복구 화면에서 직접 본 것은 아닙니다.
- 등록 스크립트는 `bputil`로 `Paired`·`1TR`인지 먼저 보고, 아니면 아무것도 바꾸지 않고 멈춥니다.
- 단계마다 실패하면 칠 다음 명령을 미리 한 번에 드립니다.
- 직전에 Asahi 이슈 #441·#404·#425의 현재 상태를 다시 봅니다.
- 1단계 파일은 D4 크기(2,097,152 B) 이하로 만듭니다. 등록 크기 한도는 모릅니다.

### 2.3 모르는 점 (실기기에서만 알 수 있음)

## 9. 막힌 것 — 소리·와이파이·블루투스 (CVP 승인 대기)

Anthropic 안전장치에 걸려 에이전트가 중단된 일입니다. **다시 시키지도, 메인 세션이 대신 하지도 않습니다**(콘치님 동의). 승인 메일의 조직 ID가 Claude Code 계정의 조직과 같은지 먼저 확인하고, 같으면 작은 일부터 다시 시켜 봅니다.

| 갈래 | 이미 된 것 | 승인 뒤 남은 일 | 근거 |
|---|---|---|---|
| 내장 스피커 | D4 단계 비프음(콘치님 3번 들음), 하드웨어 준비 모듈과 ACPI 장치 `SPK0`(Windows에 `ACPI\NWAU0001`로 보임) | `nwau_hw.cpp`, 샘플 고치기, INF, VM 빌드·서명, 설치 작업 A1·A2, 재생 시험(처음 −40 dB, 상한 −24 dB), 긴 재생·볼륨·절전 | `HANDOFF-2026-11-16-evening.md` §3.11, `research-20261116/sound/PLAN-S256.md` |
| 소리 준비의 캐시 처리 | — | 준비 모듈이 머리말·고리를 캐시를 거쳐 쓰는지 확인(에이전트 주의 1). **안전장치와 무관한 확인이라 승인 전에도 할 수 있음** | 같은 문서 |
| 와이파이(BCM4378) | 계획만(전원은 SMC GPIO 13번, 바탕 코드 후보 OpenBSD `bwfm` ISC) | 전원 켜기 → 펌웨어 올리기 → Windows에 장치로 → 최소 드라이버 → AP 검색 → WPA2 접속 → 속도·WPA3 → 서명 | `nwoas_scripts/plan-20261115/wifi.md` |
| 블루투스 | 같은 칩(`14e4:5f69`) | 와이파이 뒤 | 같은 문서 |
| HDMI 소리·이어폰 단자·내장 마이크 | 목록만 | 스피커 뒤 | `peripherals.md` 4장 |

와이파이 전원을 켜면 USB-A 주소가 밀릴 위험이 있습니다. 그래서 7장 PCIe 공통 기반(32비트 창 전체 예약, 주소 고정)은 **승인 전에 미리 해 두면** 와이파이를 바로 시작할 수 있습니다. 이 기반은 안전장치와 무관한 일반 PCIe 작업입니다.

## 10. 게임·앱 호환·보안 (상세: `graphics-compat-optimization.md` B장)

| 항목 | Vanguard 요구(가능성) | 우리 지금 | 채울 수 있나 |
|---|---|---|---|
| ARM64판 Vanguard | 필요 | Riot이 안 냄(날짜 없음) | **우리 손 밖** |
| 테스트 서명 끄기 | 요구 | 켜져 있음 | 정식 서명 필요(돈) |
| TPM 2.0 | 요구(롤 Windows 11 최소 사양에도 있음) | 없음 | M1에는 보안 세계(EL3)가 없어 하이퍼바이저가 흉내 내는 수밖에 없음. 받아 줄지 모름 |
| Secure Boot | 요구 가능 | 펌웨어에서 끄고 빌드 | 가능하나 UEFI 변수가 재부팅 뒤 남지 않음(메모리에만 있음) |
| 메모리 무결성(HVCI) | 요구 가능 | 없음 | **지금 구조로는 어려움**: Windows 자체 하이퍼바이저가 EL2에 있어야 하는데 그 자리를 우리 하이퍼바이저가 씀 [가설, 높음] |
| 가상화 아래 실행 | 거부 | Windows 밑에 하이퍼바이저가 있음 | 하이퍼바이저를 없앨 수 없음 |

- 하이퍼바이저를 없앨 수 있나: Windows는 GICv3 인터럽트 장치를 요구합니다. 다른 인터럽트 장치용 HAL 확장은 Windows 8 개발판에서 빠졌습니다. 그래서 **없애기보다 얇게** 만드는 쪽으로 갑니다. 평소 그리기·저장·화면 경로에서 하이퍼바이저를 빼고, 인터럽트·타이머·CPU 켜기만 남깁니다.
- 부정행위 방지 프로그램에게서 하이퍼바이저를 숨기는 방향은 Riot 약관 위반일 수 있어 계획하지 않습니다.
- **돈이 드는 결정은 하나입니다**: 정식 드라이버 서명용 EV 코드 서명 인증서(판매처 검색 기준 1년 약 349~359달러, 개인사업자 등록이 필요할 수 있음, Partner Center 수수료는 확인 못 함). **롤이 ARM을 지원하기 전에는 사지 않는 것을 추천합니다.** 서명만으로 롤이 되지 않고, 일상 사용은 지금 테스트 서명으로 됩니다.
- 롤 외 일상 앱: 정품 인증·Windows Update·Store는 네트워크가 생긴 뒤 확인합니다. SMBIOS(CPU 이름 등)는 작은 일입니다.
