### 4.3 배제된 것과 근거 [사실]
- 드라이버가 스스로 끊음, 칩 펌웨어 로밍(roam_off), 공유기 키 갱신, NLO·백그라운드 검색, WLAN 서비스·NCSI가 먼저 끊음: 기록상 아님.
- 통계 미응답, 검색 중 TX 보냄, PM 방식, 채널 목록 유무, 링 재개 메시지, Linux 초기 iovar, 펌웨어 로밍, 펌웨어 판(13.5).
- 링 상태: 펌웨어 쪽 쓰기 색인 사본은 호스트 값과 같음(펌웨어는 새 항목이 있는 줄 앎), 초인종 15번에도 안 읽음, 같은 시간 수신·제어 링은 정상. 링을 지우고 다시 만들면 즉시 읽음 → 멈춘 것은 연결이 아니라 **그 링 객체의 상태** [사실 + 어드바이저 해석].
- GCMP 표시: Windows 이벤트 11000/11010의 `AES-GCMP-128`은 Windows가 적은 값이고, 드라이버는 CCMP만 받으며 실제 연결도 CCMP [사실].
- RX 양 차이(판마다 30분 수신 수 다름)는 사용량 차이 [사실].

### 4.4 남은 원인 후보 [모두 가설] — 다음 세션이 가를 것
1. 채널을 벗어날 때 펌웨어가 흐름 링을 "닫고(suspend)" 돌아와 다시 여는 과정에서, 호스트가 해야 할 무엇(예: D2H로 온 메시지 중 우리가 무시하는 종류, 흐름 링 상태 응답)을 안 함. → 검색 구간의 **모든 D2H 메시지 종류·개수**와 펌웨어 콘솔(`ConsoleLive`)을 검색 전후로 비교.
2. 채널을 벗어날 때 AP에 보내는 PS null 프레임/돌아올 때의 PM 해제와 TX 큐(AC별 큐, AMPDU 세션 일시 정지)의 재개 실패. 어드바이저는 "링 객체만 다시 만들면 풀린다"는 점에서 낮게 봄.
3. 흐름 링 생성 값 중 `da`(우리는 AP 주소, Linux는 첫 프레임 목적지 — 보통 같음).
4. 폴링 방식(인터럽트 없음) — `UseInterrupt=1`이 장치 시작 실패라 아직 못 가름. 먼저 왜 시작 실패하는지(11-18 W12 기록 참고)부터.
5. 하이퍼바이저 BYPASS 경로(Windows가 BAR를 nGnRnE로 매핑해 HV가 대신 쓰기)의 타이밍. 제어·수신 링이 정상이라 낮음.
- Asahi Linux에서 같은 칩이 연결 중 검색을 해도 멀쩡하다는 것은 일반 경험이며, 이 맥미니·이 펌웨어로 확인한 적은 없습니다.
- 어드바이저 원문 판단은 이 대화 기록과 각 `RESULT-s258*.md`에 있습니다.

## 7. CPU·전력

| 언제 | 무엇을 | 결과 [사실] | 근거 |
|---|---|---|---|
| 08:21 | SMBIOS 펌웨어(s262) 부팅 | CPU 이름 "Virtual Apple M1 on m1n1 hypervisor", 8코어, 펌웨어 표 최대 3,204·현재 2,988 MHz. **Windows 표시 클럭 22~34 MHz**: 사이클 계수기가 1 µs에 약 28 증가(`CYC cyclesPerUs=28.4`, `QPF=24000000`) | `smbios-s262/runs/run-s262-wifi-20261119-082101.txt` |
| 09:07 | Cinebench (코어 종류 표+CPU 쉬기+보조 CPU 틱 100) | 첫 시도는 Claude가 `NWOAS_PWR_SECTICK=1`(10 이상이어야 함)을 넣어 실행기 검사 실패. 고친 뒤 시스템 계정 실행(C2)은 창을 못 만들어 실패 → 사용자 세션·보통 우선순위 작업(C3n)으로 **멀티 1,968.77 / 싱글 370.04** (전 1,952 / 272) | `bench-cb26/runs/cb-user-*.txt` |

- 한계: 세 기능을 함께 켜서 어느 것이 싱글을 올렸는지 모릅니다. 사용자 세션 작업도 예약 작업이라 기본 우선순위가 낮아, 보통(4)으로 지정한 `C3n`을 써야 합니다.
- 클럭 표시 [가설]: 하이퍼바이저가 PMU 사이클 계수기(PMCCNTR)를 실제 CPU 클럭이 아닌 24 MHz 근처로 보이게 함. 표시 문제라 순위 낮음.
- "Virtual … hypervisor" 이름의 출처는 확인하지 않았습니다.
- 전력 남은 시험(`NWOAS_PWR_OFF`·`SLC`·`TGAP_US`)과 기본값 결정은 그대로 남았습니다(`HANDOFF-2026-11-19.md` 5장).
