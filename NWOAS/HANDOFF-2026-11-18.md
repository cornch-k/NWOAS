## 2. 내장 스피커(S256 → S258 판들)

### 2.1 찢어지는 소리의 원인 [사실]
- mca-switch1 DMA 어댑터 값 `0x102048`은 TX_LSB_PAD=8(24비트 값이 아래쪽 정렬로 온다고 보고 8비트 더 밂). 우리 데이터는 이미 위쪽 정렬이라 두 번 밀려 넘쳐 감김 → 모든 크기에서 찢어짐(부팅음 포함).
- `0x102040`(패드 0)으로 고침(`sound-s256/audio_module.py`, `sound-s255/beep_levels.py`). 근거: Asahi `mca.c` `REG_DMA_ADAPTER_A` 필드.
- m1n1 `speaker_amp.py`는 입력을 −63 dB 줄여 넣어서 이 문제가 드러나지 않았던 것 [가설].

### 2.2 볼륨 상한과 온도 보호
| 단계 | 이득(0x03) | 볼륨 상한(0x05) | 최대 출력 | 근거 |
|---|---|---|---|---|
| 처음 | 11 dB | −24 dB | −13 dB | 보수적 |
| 정적 | 11 dB | −6 dB(0x0c) | +5 dB | speakersafetyd j274 열 모델: 연속 풀스케일 사인에 −4.6 dB 필요 |
| 보호(검증 후) | 21 dB(고정) | 모델이 정함, 최대 0 dB | +21 dB | Asahi speakersafetyd 방식(코드 새로 작성, GPL 복사 없음) |

- 앰프 V/I 감지 경로: 클러스터 0 RXB, ADMAC RX 채널 3, DMA 어댑터 B `0x205050`, 앰프 0x0e..0x10 = 0x21/0x42/0x40, 머리말 v2(감지 고리 창+0x21000).
- P1 실측 [사실]: 0.57 V·130 mA·4.35 Ω·72 mW, 기대 대비 비율 1.01~1.02 → "이득 dB = 풀스케일 사인 dBV" 가설 맞음.

### 2.3 팝·멈춤의 원인과 수정 [사실]
| 증상 | 원인 | 수정(판) |
|---|---|---|
| 중간 팝·10초쯤 멈춤 | Windows 공급(게스트 시계 QPC)과 ADMAC 소비(실제 시계) 0.8% 차이 → 큐가 바닥 근처 → 무음 끼움 | 재생 위치를 ADMAC 24 MHz 카운터로(1331-clock), 시작 무음 128 ms |
| 85 ms 넘는 처리 공백 | 재생 중 1초마다 레지스트리 디스크 쓰기, I2C를 스핀락 안에서 | 휘발성 `Live` 키, I2C는 PASSIVE 작업자(1320-worker) |
| 시작 팝 1번 | 0.39초 아날로그 이득 전환(11→21 dB) | 이득은 소리 나기 전 1번만, 미검증 상한은 볼륨으로(1403-fixgain) |
| 0.3초 볼륨 살짝 작아짐 | RX 감지 멈춤 → STALE → 상한 내림 | RX SRAM 배정, 100 ms 무수신 시 RX 재시작, 0.5초 다리(1412-bridge) — **실기 미시험** |
- 사건 기록: `Device Parameters\Live\NwAudioEvents`, `prot-tone.ps1`이 `EVT` 줄로 출력(1352-events부터).

### 2.4 지금 설치된 판·남은 일

## 3. 내장 와이파이(S257 → S259 → S258 드라이버)

### 3.1 단계별 [사실]
| 시각 | 단계 | 결과 |
|---|---|---|
| 11:36 | D4 프록시에서 펌웨어 올리기(`wifi-s257 --stage fw`) | PASS_FW_UP, 칩 BCM4378 B1(rev 3), 펌웨어 18.20.511.0.7.8.207 |
| 12:13 | 프록시에서 검색(`--stage scan`) | 11 BSS(home-ap·neighbour-ap 포함). 끝내기 DART 정리 순서 오류(전원 끈 뒤 DART 접근) → 고침 |
| 12:56/13:02 | S259: 하이퍼바이저가 UEFI 뒤 칩을 켜고 Windows에 `ACPI\NWOA4378` | 장치 보임, USB-A 정상. 첫 시도 BAR 판정식 오류(UEFI 뒤 루트 포트 명령 0x7) → 고침 |
| 13:29~14:15 | Windows 드라이버(WiFiCx) s258~s258d | 칩 접근마다 SError |
| 14:20 | 하이퍼바이저가 BAR 범위를 대신 접근(BYPASS) | **SError 0**, 펌웨어 기동 |
| 14:27 | DMA 버퍼 4 GiB 아래로(s258f) | `ready`, 검색 12~16 BSS, Windows 목록에 표시 |
| 16:10~16:25 | 접속 | s258g: EAPOL이 이벤트로 옴 → s258h: 이벤트에서 꺼내 전달 → `RxFrameFormat=1`(802.11) → **연결됨** |

### 3.2 핵심 원인들 [사실]
1. **iBoot마다 ADT phandle 번호가 다름**(macOS 26 iBoot 106, 13.5 스텁 102). 고정 비교 대신 "perst가 gpio 노드를 가리키는지"만 봄.
2. **Windows의 BAR 매핑은 Device-nGnRnE** → Apple PCIe에 non-posted 쓰기 → SError(Asahi 문서 `system-registers.md`). m1n1은 PCIe를 nGnRE로 매핑해서 프록시 스크립트는 괜찮았음. 해결: `wifi_module.py`가 `0x6e0000000+0x900000`에 BYPASS 추적기(하이퍼바이저가 EL2 nGnRE로 대신 접근, USB-A와 같은 방식).
3. **4 GiB 위 DMA는 dart-apcie0에서 안 됨**(UEFI 공유 표, FL1100도 32비트로 묶여 있음) → 드라이버 `DmaMode=0`(1 MiB~0xC0000000).
4. **이 펌웨어는 EAPOL M1을 E_EAPOL_MSG(25) 이벤트 안에 802.1X만 담아 올림** → 드라이버가 헤더를 붙여 전달.
5. **NIC가 Native 802.11** → 수신 데이터를 802.11+LLC로 넘겨야 Windows 공급자가 처리.

### 3.4 남은 일
- `RxFrameFormat=1`을 INF 기본값으로, 시험용 설정(StopAfter, 느린 모드) 기본 꺼짐 확인.
- 인터럽트(IRQ 695) 미사용, 10 ms 폴링 → 속도·전력 개선 여지.
- 속도 측정, 5 GHz·WPA3, 절전/재개, 재부팅 반복 시험, 블루투스(같은 칩 fn1 `14e4:5f69`).
- Windows `netsh wlan`은 위치 권한이 필요(콘치님 개인정보 설정, 바꾸지 않음).
