# S256 내장 스피커 — Windows 드라이버 계획과 계약

S255(2026-11-16 20:09)에서 D4 프록시만으로 스피커 소리를 냈다(`nwoas_scripts/sound-s255/beep_tone.py`, hw-path.md 끝 절). 이제 Windows가 소리를 내게 한다.

## 역할 나눔

| 누가 | 하는 일 |
|---|---|
| 런처 모듈 `nwoas_scripts/sound-s256/audio_module.py` (run_guest `-m`, Windows 시작 전) | (버전 2: 아래 "V/I 감지" 절의 감지 경로 준비도 함) 전원·AUDIO_P 리셋·NCO(48000×256)·MCA 클러스터 0 설정(직렬기 EN=0)·mca-switch1 쓰기·ADMAC TX 채널 0 리셋과 폭 설정·DART-sio 2번 통로에 고정 버퍼 매핑·같은 버퍼를 게스트 IPA 창에 매핑·앰프 GPIO 리셋 해제, 볼륨 0x05=0x50, 설정 레지스터 쓰기, **앰프는 꺼짐(0x02=0x0e)으로 둠**·창 머리말 쓰기 |
| Mu 펌웨어 SSDT | 장치 `SPK0` `_HID "NWAU0001"`, 자원 아래 표 |
| Windows 드라이버 `port-j274/sound/nwoas-audio/` (PortCls WaveRT, Microsoft SimpleAudioSample 바탕) | 48 kHz 렌더 끝점. 타이머로 Windows 버퍼 → 창의 고리 버퍼(모노 24비트를 32비트 상위 정렬)로 변환 복사, ADMAC 기술자 보충, 재생 시작·정지 때 직렬기와 앰프 켜고 끄기, 볼륨을 앰프 0x05로(상한 강제) |

## ACPI 자원 (순서 고정)

| # | 무엇 | 주소 | 크기 |
|---|---|---|---|
| 0 | I2C1 | 0x235014000 | 0x4000 |
| 1 | ADMAC | 0x238200000 | 0x34000 |
| 2 | MCA 클러스터 (mca-switch reg0) | 0x238400000 | 0x18000 |
| 3 | MCA switch1 (mca-switch reg1) | 0x238300000 | 0x30000 |
| 4 | 소리 창 (게스트 IPA, 런처가 정함, 겹침 검사) | 런처 모듈 상수 | 0x40000 |

인터럽트는 1단계에서 쓰지 않는다(드라이버 타이머).

## 창 머리말 (자원 4의 처음 0x1000, 런처가 씀, 드라이버는 읽기만)

| 오프셋 | 형 | 값 |
|---|---|---|
| 0x00 | u32 | magic 0x5541574e ('NWAU') |
| 0x04 | u32 | version 1 |
| 0x08 | u64 | ring_iova: 고리 버퍼(창+0x1000)의 DART-sio 2번 통로 IOVA |
| 0x10 | u32 | ring_bytes (0x20000) |
| 0x14 | u32 | sample_rate 48000 |
| 0x18 | u32 | 형식 1 = 모노, 24비트 부호 있는 값을 32비트 상위 정렬(값 << 8) |
| 0x1c | u32 | ADMAC TX 채널 0 |
| 0x20 | u32 | MCA 클러스터 0 |
| 0x24 | u32 | 앰프 I2C 주소 0x31 |
| 0x28 | u32 | 볼륨 상한: 앰프 0x05에 쓸 수 있는 가장 작은 값(= 가장 큰 소리). 1단계 0x30(−24 dB) |
| 0x2c | u32 | 상태: bit0 = 런처가 하드웨어 준비 완료, bit1 = V/I 감지 경로 준비 완료(버전 2만) |

### 머리말 버전 2 (2026-11-18 S259, 0x4c 바이트) — 스피커 열 보호용

결론: 버전 2는 버전 1 뒤에 7칸을 더합니다. 드라이버는 버전 1과 2를 모두 받습니다. 버전 1이거나 bit1이 0이면 감지 없이 고정 상한(정적 모드)만 씁니다.

| 오프셋 | 형 | 값 |
|---|---|---|
| 0x04 | u32 | version 2 |
| 0x30 | u64 | sense_iova: 감지 고리(창+0x21000)의 DART-sio 2번 통로 IOVA. 창 IOVA = ring_iova − 0x1000 |
| 0x38 | u32 | sense_bytes 0x10000(4 KiB × 16, 묶음 하나 = 1024 프레임 = 21.3 ms). TX 고리 뒤·창 안이어야 함 |
| 0x3c | u32 | ADMAC RX 채널 3(클러스터 0 RXB). 홀수, TX 채널과 같은 4개 묶음 |
| 0x40 | u32 | 형식 2 = 프레임마다 32비트 1워드: 비트15:0 = I(s16), 비트31:16 = V(s16) |
| 0x44 | u32 | prot_gain: 0 = 보호 끔(감지·모델만 돌고 이득은 0x00), 0x14 = 보호가 정상일 때 이득 21 dB 허용 |
| 0x48 | u32 | prot_vol_floor: 이득 0x14일 때 0x05에 쓸 수 있는 가장 작은 값(단계별 상한) |

런처 환경 변수 `NWOAS_AUDIO_PROT`가 0x44/0x48을 정합니다(모듈 지문은 그대로).

| 값 | prot_gain | prot_vol_floor | 이득 0x14일 때 최대 출력(풀스케일 사인) [가설: 이득 dB = dBV] |
|---|---|---|---|
| `sense`(기본) | 0x00 | 0xc9 | 이득이 안 올라감: 정적 +5 dBV |
| `moderate` | 0x14 | 0x18 | +9 dBV |
| `full` | 0x14 | 0x00 | +21 dBV (Asahi + speakersafetyd와 같은 한도) |

## 안전 규칙 (드라이버가 지킴)

모든 앰프 쓰기는 `nwau_core.c`의 `nwau_amp_write_allowed()` 한 곳에서 검사합니다(단위 시험으로 모든 이득·볼륨 조합 확인).

- 정적 모드(이득 0x00): 0x05 ≥ max(머리말 0x28, 0x0c) → 풀스케일 +5 dBV 이하.
- 보호 설정됨(머리말 버전 2·bit1·prot_gain 0x14, S259e): 이득 0x14를 앰프가 꺼진 동안 쓰고 재생 내내 유지(아날로그 이득 전환 없음).
  - 미검증(정적): 0x05 ≥ 0x0c + 0x14 = 0x20 → 풀스케일 +5 dBV(정적 모드와 같음).
  - 검증(열 모델 정상): 0x05 ≥ max(모델 하한, prot_vol_floor). 천장은 10 ms에 0.5 dB씩만 올라감.
  - 감지가 끊기거나 이상하면: 천장을 0x20으로 바로 내림(2 dB씩 0.5 ms 간격). 그 뒤 다시 검증되면 다시 올림.
  - 절전·드라이버 내림 때만 앰프가 꺼진 상태에서 이득 0x00으로 돌려놓음.
  - 이득을 모르는 상태(쓰기·되읽기 실패)는 0x14로 보고, 그 상태의 볼륨 하한은 정적과 같은 크기(0x0c + 0x14 = 0x20).
- 0x03에는 0x00(언제나)과 0x14(보호 설정 + 확인된 볼륨이 0x14 기준 하한 이상)만, 0x01(소프트 리셋: 0 dB·19 dB 기본값으로 돌아감)·0x00(page)·0x7f(book)는 쓰지 않는다.
- 0x02=0x0c 또는 0x00(동작, 감지 켬)은 직렬기가 켜져 있고 ADMAC에 데이터가 들어간 뒤에만. 감지 켜기는 종료 상태에서 0x0e → 0x02로 비트를 바꾼 뒤 0x00. 켤 때: 볼륨 0xc9 → 무음이 큐에 있는 채로 동작 → 볼륨 램프. 정지·장치 제거·절전·언로드·열 한계 초과에서는 볼륨 0xc9까지 약 5 ms 램프 → 0x0d → 0x0e(절전·언로드 때만 이득 0x00).
- 머리말 magic/version/bit0이 맞지 않으면 장치 시작 실패(소리 없음).

## V/I 감지와 열 보호 (2026-11-18 S259)

결론: 런처가 감지 경로를 준비하고(전부 꺼 둔 채), 드라이버가 재생마다 켜고 1024 프레임마다 모델을 돌립니다. 모델·검사는 `nwau_core.c`의 순수 C 코드이고 단위 시험을 통과했습니다. **실기기 검증 전입니다.**

| 누가 | 하는 일 |
|---|---|
| 런처(S1~S4) | ADMAC RX 채널 3 리셋(16비트 워드, 2워드 프레임, burst 0x600030, 꺼 둠) · MCA 클러스터 0 RXB(16슬롯×16비트, 슬롯 0·1, 포트 0, SYNC 1, BCLK_POL 1, EN=0) · DMA 어댑터 B(switch1+0x4000) = 0x205050 · 앰프 0x0e..0x10 = 0x21, 0x42, 0x40(종료 상태에서) · 머리말 bit1 |
| 드라이버(재생 시작) | 앰프 감지 설정 다시 쓰고 되읽기 → RX 채널 리셋 → 묶음 4개에 표시값(0x5a5aa5a5) 채워 기술자 넣기 → RX 켜기 → RXB 리셋 펄스(50 µs) 후 EN → 앰프 0x02 → 0x00 |
| 드라이버(재생 중) | 완료된 RX 묶음마다 `nwau_ts_block()`: V·I·전력·임피던스 계산, 보낸 신호와 비교, 2단 열 모델 갱신 → 볼륨 하한 |
| 드라이버(S259b) | 묶음 8 KiB(2048 프레임). 앰프 I2C는 PASSIVE·`AmpMutex`에서만(스핀락 밖). RX가 150 ms 멈추면 다시 시작해 재판정(재생마다 5번까지), 그동안 정적 모드 + 보낸 신호로 모델(4.0 Ω). 재생 중 기록은 휘발성 `Device Parameters\Live`에만 |

**열 모델(speakersafetyd j274 수치, 식은 새로 작성):** 코일 목표 = 자석 + P×40 °C/W, 자석 목표 = 46 + P×60 °C/W, 시정수 3.7 s / 250 s(묶음마다 정확한 1차 단계). 표시 온도 = max(코일, 자석)에 5 °C 지연(내려갈 때만). 120 °C(140 − 20)부터 감쇠가 선형으로 커져 140 °C에서 17.65 dB(21 dB 이득에서 연속 0.94 W). 180 °C(140 + 40)를 넘으면 앰프 끔(정지 사유 9). 켜질 때 코일 119 °C·자석 89.8 °C로 가정(speakersafetyd 첫 부팅 규칙). 멈춘 동안은 두 단 결합 해로 식힘. 드라이버 재시작 때는 레지스트리에 남긴 상태를 식힌 값과 가정값 중 큰 쪽.

**저항 → 온도:** R = Σv·i / Σi², T = 25 + (Rmin/4.6 − 1)/0.0037. **보고만 합니다**(Rref가 실측되지 않아 제한에 쓰지 않음).

**정상 판정과 되돌림:**

| 조건 | 결과 |
|---|---|
| 재생 시작(또는 RX 재시작) 뒤 첫 묶음 | 판정 안 함, 모델은 보낸 신호의 전력(4.6 Ω)으로 계산 |
| 보낸 신호 0.2 Vrms 이상이고 측정/기대 V² 비가 −3..+3 dB, 임피던스 2~30 Ω, 저항분 1 Ω 이상인 묶음 6개(묶음 42.7 ms) | 정상(HEALTHY) → 이득 0x14 허용. V·I가 둘 다 절반으로 읽혀도(전력 1/4) 정상이 되지 않음 |
| 묶음 없음 100 ms | (정상 상태) RX 조용히 재시작, 보호 상태 유지 |
| 묶음 없음 150 ms~0.5 s, 정상이고 모델 110 °C 밑 | 되돌리지 않음(다리): 보낸 신호(4.0 Ω)로 모델 계속, 천장 유지 |
| 묶음 없음 150 ms(미검증이거나 뜨거움) 또는 0.5 s 넘음 | 되돌림(STALE) → RX 재시작·재판정 |
| 묶음의 25 % 넘게 표시값 그대로 | 즉시 되돌림(UNWRITTEN) → RX 재시작·재판정 |
| 평균 전력 −10 mW 미만 / 임피던스 범위 밖 / 보낸 신호가 작은데 3 % 넘게 포화 — 3묶음 연속 | 되돌림 |
| 보낸 신호 0.2 Vrms 이상인데 측정 V²가 −8 dB 아래 — 3묶음 연속 | 되돌림(DEAD) |
| 위 이상 묶음 동안 | 모델 입력 = max(측정 전력, 보낸 신호 전력) |
| 보낸 신호가 감지 한계(14 V) 12 dB 안이라 포화 | 이상 아님, 모델은 보낸 신호 전력 |

되돌린 재생이 끝난 뒤 다음 재생은 모델 온도를 가정값(119 °C) 이상으로 올리고 시작합니다(정적 모드 최악 정상상태 115 °C보다 높음).
