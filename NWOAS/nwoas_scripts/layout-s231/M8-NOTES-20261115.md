# M8 (C guest launcher) partial findings — 2026-11-15

Read-only design pass stopped early (design document not produced). Facts below come from source files and
the S231 log `logs/layout-s231-20261115-181130.tcRgQH`; none is hardware-validated for a hostless boot.

1. MSR traffic still handled by host Python `handle_msr` during the guest m1n1 prefix: OSLAR_EL1, HID5, EHID9,
   EHID10, EHID20 accesses and ACC_CFG writes (Skip). Log lines "Pass:" / "Skip:". A hostless HV needs C handling.
2. HACR_EL2 is overwritten wholesale by Python (`m1n1_windows/proxyclient/m1n1/hv/__init__.py:1911-1924`);
   the BIT(56) set by C hv_init survives only because the Python value includes it.
3. Python ADT rebuild adds root property `pmgr-u8id` (4 bytes, 0) (`m1n1/adt.py:812-830`); otherwise round-trips.
   Account for this when diffing a C-built ADT against the Python one.
4. Observed layout (this run): phys_base 0x83bd04000, guest_base 0x83cdc0000, entry 0x83cdc0800,
   BootArgs 0x83f3b8000, low-4GiB window backing 0xae0fcc000, mem_size 0x3a52fc000 -> 0x2a52fc000 after S102 shrink.
5. phys_base differs every run (8 of last 9 logs: 0x83b99c000 .. 0x83d38c000), so C-vs-Python diffs must
   normalise to phys_base-relative values or pin phys_base.
