DEFECTS (claim precision only)
1. display-s241/README.md:139 (and the report): "hv_vm.c:1153-1155 … also read-only".
   - FACT: that code is compiled out (hv_vm.c:1140 `#define NWOAS_HID_EXTENDED_OBSERVER 0`).
   - The FBMASK probe is not purely read-only either. hv_exc.c:251 runs `dc_ivac_range` (invalidate without clean) over the first 3.6 MB.
   - HYPOTHESIS: this can drop dirty guest framebuffer lines. If so the damage is visual only. The behaviour is the same for 720p and 1080p and is not introduced by S241.
   - Fix: reword to "tile-hash code disabled at hv_vm.c:1140; FBMASK reads after a dc ivac of the first 3.6 MB (pre-existing, display memory only)".
2. display-s241/README.md:160: "No disk, NVRAM, m1n1, Mu or Windows state depends on these files".
   - This is unverified for Windows. A 1080p boot may make Windows store a display configuration for the new mode in the registry on the guest disk.
   - Fix: mark the Windows part as HYPOTHESIS. It may persist a per-mode display configuration, which a 720p boot is expected to replace.
