DEFECTS
1. MEDIUM — README.md §5 step 1 (around line 108) has no rollback path. It removes badmemorylist before S237 is proven. If step 2 shows "could NOT reserve" or U3 fails, going back to S223 leaves USB-A unprotected.
   Fix: add "on any stop or fail, queue usb-s236/B1-set-badmemory.cmd before returning to S223".
2. MEDIUM, verification gap — M1-memmap.ps1:9-24 only shows that Windows RAM excludes 0xC0000000–0xC00FFFFF. It never checks that under Windows the FL1100 BAR and root-port-1 window are still at bus 0xC0000000, which is CPU 0x6C0000000.
   - HYPOTHESIS risk: if pci.sys relocates or rebalances the window, M1 prints EXCLUDED while the real window overlaps RAM, a false pass.
   - Fix: also print the memory resources of the xHCI device and root port 1 (Win32_DeviceMemoryAddress, or the PnP Manager resource map). Report bus = CPU − 0x600000000 and flag any value outside [0xC0000000, 0xC0100000).
3. LOW — validate-s237.sh:44-45 and 59-60 only log the M1 output.
   - A cycle with INCLUDED, an empty JOBOUT (PowerShell exception) or a missing S237 HVLOG line still counts toward "6/6".
   - Fix: abort, or mark the cycle FAIL, when JOBOUT lacks "EXCLUDED" or contains "INCLUDED|badmemorylist".
4. LOW, reproducibility wording — README.md:94-99 cannot be re-run as written.
   - `mkdir fw-s237-mu-s237` fails because the kept tree already exists.
   - Bit-exactness also depends on the real tree path, not just the X31 logical path. The PDB stores the real working directory. That is why s237 vs repro3, both built via the X31 path, still differ in 78 RSDS hashes (FACT, re-run).
   - Fix: state "bit-exact only with the same real path and the same logical path", and give a `--rebuild-only` recipe for the kept tree.
5. LOW — the disassembly excerpt shows `bl 0x7838` with no symbol. "bl ReserveMemoryRegion" is therefore an inference from the argument registers and the result test.
   Fix: label it as an inference, or add the symbol address from the map or PDB.
