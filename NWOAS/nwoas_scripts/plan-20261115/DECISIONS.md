# 결정 기록 (2026-11-15, 콘치님이 판단을 맡김)

| 번호 | 결정 | 이유 | 되돌리기 |
|---|---|---|---|
| D1 | Windows 부팅 항목(스텁)에는 macOS 13.5 펌웨어 묶음을 쓴다. macOS 본체와 시스템 펌웨어는 Tahoe 그대로 둔다 | 공개 GPU 드라이버(windows-on-m1)가 13.5 GPU 펌웨어만 지원한다. 이 맥미니에서 7월에 13.5 묶음으로 HDMI 화면까지 띄운 기록이 있다. 9월 6일 "Tahoe 유지" 지시는 시스템 펌웨어와 macOS를 두고 한 것이므로 그대로 지켜진다 | 스텁을 다시 만들거나 26.x 묶음으로 바꾸면 된다. macOS에는 영향이 없다 |
| D2 | 네이티브 SSD 드라이버는 "검사하는 직접 방식"으로 간다. 데이터는 장치가 직접 옮기고, 명령을 넣는 순간에만 하이퍼바이저가 LBA 범위와 메모리 주소를 검사한다 | 순수 직접 방식은 macOS 파티션 보호(쓰기 구역, GPT 보호)를 모두 없앤다. 지금의 중계 방식은 느리다 | 중계 방식(S231)은 그대로 비교 기준·복구 경로로 남는다 |
| D3 | 네트워크는 내장 와이파이를 우선한다 | 콘치님 지시 | — |
| D4 | USB 원인 시험에 `bcdedit truncatememory 0x100000000`을 쓴다 (Windows 메모리를 4GB로 줄임) | 32비트 임시 버퍼 경로를 배제하는 가장 값싼 시험이다(Fable 어드바이저 추천). 다시 빌드할 필요가 없다 | `bcdedit /deletevalue {default} truncatememory` |
| D5 | 통합 방식: windows-on-m1 코드를 바탕으로 J274 설정을 얹는다. S231은 비교 기준으로 얼려 둔다 | 그쪽 GPU·SSD·단독 부팅이 모두 그쪽 하이퍼바이저 핵심 파일에 기대고 있다(port/strategy.md) | S231 실행 스크립트가 그대로 남아 있다 |
| D6 | 개발 중에는 맥북 연결 모드를 유지하고, 맥북 없는 부팅은 마지막에 완성한다 | 드라이버 개발·디버깅에는 하이퍼바이저 로그와 원격 작업 통로가 필요하다 | — |
