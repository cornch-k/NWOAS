# file-delivery-s168/client — native ARM64 Windows no-CRT delivery client

A freestanding, no-CRT ARM64 Windows executable that pulls **one** known,
immutable host artifact — the official Cinebench zip — over the S168 delivery
channel (`../channel.py`) that lives in the pre-FAT gap of the existing
transport-s123 NS2 host-RAM image. Built the same way as
`../../native-link-s125` (clang `--target=aarch64-pc-windows-msvc`, lld-link,
`/nodefaultlib`, own minimal `kernel32.def`).

It does **no** hardware/USB/guest actions of its own: it only opens the virtual
NS2 disk the NWOS worker already exposes and reuses that worker's session token.

## Files
- `wire.h` — pure, platform-independent (`<stdint.h>` only) wire logic mirroring
  `../channel.py`: CRC-32, request builder, response parse/validate. Included by
  both the client and the host test.
- `nwoas_client.c` — the no-CRT client (`mainCRTStartup`). Win32 typedefs and
  imports live here, separate from `wire.h`.
- `kernel32.def` — the only imports used (13 functions, verified with
  `llvm-readobj --coff-imports`).
- `build.sh` — builds `NWOAS-S168.EXE` with `-Wall -Wextra -Werror` (zero warnings).
- `gen_vectors.py` / `test_wire.c` / `test_host.sh` — host-native unit test of
  the pure helpers against golden vectors generated from the real `../channel.py`.
- `vectors.h` — generated by `test_host.sh` (not hand-edited).

## Behaviour
1. Guard: `GetDiskFreeSpaceExW("C:\\")` must show ≥ `zip + 512 MiB` free.
2. Identify NS2 exactly (length `8448*4096`, MBR sig `0x53313233`, `55 AA`,
   `NWOAS-S123-LINK!` at LBA 128); capture the token read-only, reopen
   `GENERIC_READ|WRITE` with `FILE_FLAG_NO_BUFFERING` and page-aligned
   `VirtualAlloc` buffers, then **re-verify the token**.
3. Manifest request (id 1, SENTINEL offset, length 0). Reject unless the
   advertised `file_size` (`783373346`) and SHA-256
   (`cb6c765f…78159`) match the known official zip.
4. Open `C:\NWOAS-BENCH\CINEBEN.ZIP.part` `CREATE_NEW` (never overwrite/resume;
   folder is pre-created by the wrapper).
5. Monotonic full-cap (`65408 B`) requests; the channel returns a final-short
   chunk. Each response is validated for magic/token/header-CRC(`0:124`)/payload-CRC
   and echoed id/offset/status/size. An identical request is retried at most 3×.
6. Sequential buffered `WriteFile`, then `FlushFileBuffers` + `CloseHandle`;
   **no rename**.

## Block discipline
The **only** block ever written is **LBA 127** (one 4096-B request per exchange).
LBA 128 (the worker's mailbox and its ACK sequence) is **read** for the token but
**never written**, so the existing PORT-128 worker sequence is untouched.
Responses are read from LBA 129 as a single aligned 64 KiB request.

## Integrity scope (important)
The per-chunk header and payload CRC-32s prove **transport integrity only** —
they are **not** a full-file hash. The authoritative full-file SHA-256
verification and the rename to the final `.ZIP` are performed by a **separate
PowerShell step** after this executable exits with code `0`. The manifest
size/SHA match is a bring-up sanity check against a known constant, not a
verification of the bytes actually written to disk.

## Build & test
```sh
sh build.sh       # -> NWOAS-S168.EXE (ARM64 PE, no CRT, zero warnings)
sh test_host.sh   # pure-logic unit test vs ../channel.py golden vectors
```
`test_host.sh` exercises in-memory validation only; it says nothing about
hardware and makes no such claim.
