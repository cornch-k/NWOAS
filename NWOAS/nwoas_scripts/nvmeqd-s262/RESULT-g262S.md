# S262S — 동시 처리를 켜도 빨라지지 않은 원인과 고친 것 (2026-11-19 06시)

표기: **[사실]** = 기록·코드·이 맥북에서 돌린 결과로 확인, **[가설]** = 확인하지 않은 추측, **[빌드만]** = 빌드·호스트 시험까지만 됨.

## 0. 결론

1. **명령을 한 번에 하나씩 넣은 쪽은 하이퍼바이저도 SSD도 아니고 Windows였습니다.** 하이퍼바이저는 Windows가 문을 두드린 지 2 µs 안에 SSD로 넘겼고, 새 명령을 넣는 순간마다 이미 진행 중인 명령이 없었습니다(진행 중 평균 1.00). [사실: 계수기]
2. **Windows가 그렇게 한 까닭은 시험 프로그램의 입출력 우선순위가 "낮음"이었기 때문으로 봅니다.** 시험 작업을 돌리는 "NWOAS Agent" 예약 작업이 우선순위 없이 만들어져 기본값 7(입출력 우선순위 낮음)로 돕니다. Windows 디스크 드라이버(classpnp)는 우선순위가 낮음 이하인 입출력을 "한가할 때 처리할 요청"으로 따로 줄 세우고, 기본으로 **1개만** 장치에 넣으며 다음 것은 앞 것이 끝난 뒤에 넣습니다. [사실: 스크립트·Microsoft 문서·공개 소스] 이것이 이번 결과의 원인이라는 것은 [가설, 근거 강함] — 실기에서 아래 A1/A2 비교로 확정합니다.
3. **그래서 고칠 곳은 하이퍼바이저가 아니라 시험을 돌리는 방식입니다.** 시험 프로그램을 입출력 우선순위 "보통"으로 띄우는 작은 도구 `NWIOP.EXE`와 그것을 쓰는 작업 `Q1S`를 만들었습니다. 같은 부팅에서 옛 방식(Q1)과 새 방식(Q1S)을 나란히 잽니다. [빌드만]
4. **하이퍼바이저 g262S 바이너리는 만들지 않았습니다.** 하이퍼바이저가 줄을 세운 증거가 없어 바꿀 곳이 없기 때문입니다. `NWOAS_S262_HV=1`은 지금처럼 g262R을 씁니다. 다만 QD1이 엔진을 켜면 11% 느려지는 것은 하이퍼바이저 쪽 비용이며(4장), 동시 처리가 실제로 일어나는 것을 본 뒤에 따로 다룹니다.
5. **일반 Windows 사용(앱·탐색기 등)은 이 제한을 받지 않았을 것입니다.** 보통 프로그램은 입출력 우선순위가 보통이기 때문입니다. 부팅 중에는 실제로 32개까지 동시에 들어갔습니다(태그가 모자라 기다린 횟수 696회). [사실: 계수기] 사용자 체감에 이미 효과가 있는지는 [가설].
6. **맥미니에서는 아무것도 하지 않았습니다**(와이파이 시험 진행 중).

## 2. 왜 Windows가 하나씩 넣었는가

결론: 시험 프로그램의 입출력 우선순위가 "낮음"이고, Windows 디스크 드라이버는 낮은 우선순위 입출력을 기본으로 하나씩만 장치에 넣습니다. [사실: 각 고리] 이 고리가 이번 결과를 만들었다는 것은 [가설].

| 고리 | 내용 | 근거 |
|---|---|---|
| 1. 작업 실행기 | "NWOAS Agent"를 `schtasks.exe /Create /TN "NWOAS Agent" /SC ONSTART /RU SYSTEM /RL HIGHEST …`로 만듦. 우선순위 지정 없음 | [사실] `layout-s231/jobs/J5-bcdboot-stage.cmd:30` (현재 설치), 예전 `native-link-s125/install-autostart.cmd:7` |
| 2. 기본 우선순위 | 예약 작업 기본값 7 = BELOW_NORMAL, 입출력 우선순위 IoPriorityLow, 메모리 우선순위 LOW | [사실] Microsoft Learn "Priority (settingsType) Element" 표 |
| 3. 물려받음 | 에이전트 → cmd.exe → NWPWR/NWQD가 같은 우선순위로 돎 | [가설] — `NWIOP.EXE`가 첫 줄에 자기 우선순위를 찍어 확인 |
| 4. 디스크 드라이버 | 우선순위 ≤ IoPriorityLow인 입출력은 "idle request"로 줄에 넣고, 동시에 장치에 둘 수 있는 수 `IdleActiveIoMax` 기본값 **1**, 다음 것은 앞 것의 완료 처리에서 넣음. 보통 입출력이 진행 중이면 넣지 않고 12 ms 기다림 | [사실] Windows-driver-samples `storage/class/classpnp/src/classp.h:1224-1231`, `clntirp.c:174-237, 715-732`, `class.c:2554` (공개 예제 소스; Windows 11에 든 classpnp가 같은지는 [가설]) |
| 5. 부팅 중과의 차이 | 부팅 중 입출력은 대부분 시스템의 보통 우선순위라 32개까지 동시에 들어감 | [사실: 1.1표] + [가설: 우선순위 구분] |

- 지연 최댓값이 약 250 ms(QD1 248,693 µs 등)로 반복되는 것도 "보통 입출력이 끼면 낮은 것은 뒤로 밀림"과 맞습니다. [가설]
- 이 고리는 g262Q 이전부터 같았으므로, QD를 끈 옛 경로의 측정값도 "낮은 우선순위로 잰 값"입니다. 다만 옛 경로는 하이퍼바이저가 명령을 끝까지 기다리므로 어차피 하나씩입니다.

## 5. 위험 [모두 가설]

1. **보통 우선순위가 되면 처음으로 SSD에 4K 명령이 오래 여러 개 들어갑니다.** 부팅 중 32개 동시는 이미 있었지만, 384 MiB 쓰기·덮어쓰기를 동시에 하는 것은 처음입니다. 무결성 검사와 재시작 뒤 검사가 이를 잡도록 되어 있습니다.
2. 공개 classpnp 예제와 Windows 11에 든 드라이버가 다를 수 있습니다. 그러면 A2에서 진행 중 평균이 1.00으로 남고, 2장 가설은 버립니다.
3. 우선순위를 높인 시험이 도는 동안 다른 시스템 입출력이 조금 밀릴 수 있습니다(시험 시간 동안만).
4. `NWIOP.EXE`는 Windows에서 돌려 보지 않았습니다. 우선순위 설정이 거부되면 시험 프로그램을 시작하지 않고 91로 끝나며, 단계 스크립트가 멈추고 옛 경로로 되돌립니다.
