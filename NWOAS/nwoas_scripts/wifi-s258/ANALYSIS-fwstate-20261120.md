# 와이파이 송신 링 멈춤 — 펌웨어 안의 상태를 직접 본 결과 (2026-11-20 새벽)

> 표기: **[사실]** = 실기 기록·펌웨어 분해로 확인, **[가설]** = 아직 확인 안 됨. 와이파이 이름·주소는 드라이버가 비교 전에 덮어써서 어디에도 없습니다(EB = 공유기 주소, EA = 자기 MAC, E5 = 이름).

## 0. 결론

**멈춤의 직접 원인은 펌웨어가 송신 링마다 가진 "닫힘" 표시(상태 값의 비트 2)가 검색 중에 켜지고 다시 꺼지지 않는 것입니다 [사실]. 닫는 명령은 "인터페이스 닫기"(명령 번호 10)로 검색 한 번에 정확히 100번 오고, 이 링에 적용된 여는 명령은 0번입니다 [사실](링과 번호가 맞지 않아 적용 안 된 열기가 있었는지는 이 기록으로 알 수 없음). 왜 "인터페이스 열기"(9)가 안 오는지는 아직 모릅니다 — 이것이 남은 근본 원인입니다.**

## 2. 펌웨어 분해로 확인한 것 [사실] (13.5 펌웨어 18.20.383, 파일이 곧 RAM 0x352000부터의 내용)

링 구조체(크기 0xE0, 이름 "txfl0", "txfl1"…):

| 오프셋 | 내용 |
|---|---|
| +0x01 | 이름 문자열 |
| +0x1e | 8비트, 우리 링에서는 0xFF (가설: 상대 단말 번호, 배정 안 됨) |
| +0x22 | 링 번호(2, 3) |
| +0x24 | 상태 16비트. 비트 2 = 닫힘 |
| +0x26 / +0x2c | 출발지(자기 MAC) / 목적지(공유기 주소) |
| +0x32, +0x33 | 8비트 둘, 우리 링에서는 0, 0 (가설: tid, 인터페이스 번호) |
| +0x78 | 열기·닫기 기록 구조체 포인터: 열기 시각 5개 +0x2c, 열기 횟수 +0x40, 닫기 시각 5개 +0x5c, 닫기 횟수 +0x70, 열기 이유 5개 +0x10c, 닫기 이유 5개 +0x120 |

비트 2를 켜고 끄는 함수와, 그것을 부르는 명령 분배 함수(0x38809c, 장치 함수표 0x4300c0에 등록):

| 명령 번호 | 함수 | 링을 고르는 기준 | 뜻 |
|---|---|---|---|
| 1 / 2 | 0x3861e8 | 링 +0x1e == 인자[2] | MAC 열기 / 닫기 |
| 6 / 7 | 0x386578 | 주소(인자+8) | MAC 설명 추가 / 삭제 |
| 9 / 10 | 0x3863b0 | 링 +0x33 == 인자[4] | 인터페이스 열기 / 닫기 |
| 0x14 / 0x15 | 0x38649c | 링 +0x33, +0x32 | tid 열기 / 닫기 |
| 0x1a / 0x1b | 0x3862e8 | 링 +0x22 == 인자[0] | 링 번호로 열기 / 닫기 |

신호 번호 1, 2, 6, 9, 10의 뜻은 brcmfmac `fwsignal.c:46-55`(MAC_OPEN 1, MAC_CLOSE 2, MACDESC_ADD 6, INTERFACE_OPEN 9, INTERFACE_CLOSE 10)에서 확인했습니다 [사실]. 0x14/0x15, 0x1a/0x1b의 이름은 함수 동작에서 짐작한 것입니다 [가설]. 기록에 남는 "이유"는 이 명령 번호 그대로입니다. 실기 기록의 이유 10 = 인터페이스 닫기.

## 3. 아직 모르는 것 [가설]

- 명령 9(인터페이스 열기)를 펌웨어 윗단이 아예 안 보내는지, 보내는데 링과 맞지 않는 번호로 보내는지. 링에 남는 기록은 "맞은 것"만 적히므로 구분되지 않습니다.
- 윗단(명령을 내리는 쪽) 코드는 파일에 없는 ROM(0x352000 아래 주소)에 있을 가능성이 큽니다. 파일 안에서 명령 9/10을 넣어 부르는 자리는 찾지 못했습니다.
- Linux에서 같은 닫기 100번이 오는지, 열기가 오는지.
- s273에서 함께 바뀌던 다른 두 값(3→0x10003, 그 0x470 뒤 0x618→0)이 무엇인지.
