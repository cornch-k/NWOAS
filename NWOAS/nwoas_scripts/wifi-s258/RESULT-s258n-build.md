# 와이파이 s258n(1.0.1.5) 빌드 결과와 실기 시험 순서 (2026-11-19 05:46)

## 결론
**"약 270초마다 끊김"의 실체는 연결마다 한 번씩 생기는 송신 멈춤입니다. 칩 펌웨어가 송신 패킷을 받아 두고 완료를 돌려주지 않으며, Windows가 1~2.5분 뒤 연결을 끊었다 다시 붙일 때에야 한꺼번에 돌려줍니다 [사실].** 드라이버 쪽 링 되감기, 버퍼 고갈, 색인 갱신은 원인이 아닙니다(1장 표). 128개 송신 칸이 다 차는 것은 Windows가 복구를 그만둔 뒤의 결과입니다 [사실].
**멈춤은 Windows가 연결 180초 뒤 요청하는 "연결 중 검색"과 맞물려 있습니다 [가설, 근거 강함, 증명 전].** 검색 전에 찍힌 상태 8번은 모두 송신 미완료 0개였고, 검색 뒤 80초 넘게 지나 찍힌 5번은 모두 26~128개였습니다(2장).
**s258n은 (1) 연결 중에는 펌웨어 검색을 하지 않고(기본값, 레지스트리로 되돌림), (2) 그래도 멈추면 드라이버가 8초 안에 알아채 단계별로 되살리며, (3) 다음 실행에서 원인을 판정할 기록(링 색인, 버퍼 수, 펌웨어 콘솔, 펌웨어 계수, 모든 펌웨어 이벤트)을 남깁니다.** 빌드·서명·INF 검사·단위 시험 178개는 통과했고, 맥미니에서는 아직 돌리지 않았습니다 [빌드만].

| base에서도 멈춤 | 검색은 원인 아님. `NwoaStallLog`의 `age`(연결 나이), `NwoaEvAll`의 직전 이벤트, `NwoaConsoleLive`, `NwoaFwCntBase`↔`Stall` 차이로 펌웨어 원인을 찾음 |
| `a4`(PM으로 회복) | 펌웨어 전원 절약 상태 문제 쪽 |
| `a5`(흐름 링으로 회복) | 흐름 링·송신 대기열 문제 쪽 |
| `a3`만 | 연결 단위 상태 문제. 회복은 되지만 매번 2~3초 끊김 |
| `fl<w>/<r>`에서 w≠r | 펌웨어가 흐름 링에서 가져가지도 않음 / w=r이면 가져간 뒤 붙잡음 |

## 7. 확인 안 된 것
- 맥미니에서는 아무것도 돌리지 않았습니다. 감시의 ③ 단계 뒤 Windows가 곧바로 다시 연결하는지, 검색을 생략해도 Windows가 문제 삼지 않는지는 실기에서만 압니다 [빌드만].
- `Get-NetAdapterStatistics`의 수신 수(유니캐스트 145, 브로드캐스트 8)와 드라이버 `NwoaCntRx`(2,081)의 차이는 멀티캐스트 수를 보지 않아 판단하지 않았습니다.
- DHCP-Client 50065/50067 쌍(다시 연결할 때마다)은 읽지 않았습니다.
- 펌웨어 `counters` 덤프의 배치(이 펌웨어 판의 wl_cnt 형식)는 아직 풀지 않았습니다.
