**Files created** (all new, in /Users/angigyeom/Desktop/DEV/NWOAS/nwoas_scripts/wifi-s240/):
- `/Users/angigyeom/Desktop/DEV/NWOAS/nwoas_scripts/wifi-s240/wifi_probe.py` — the probe (sha256 2408a15b…5394). By default it only prints the plan and opens nothing. With `--run`:
  1. **Guards:** `lsof` must show both CDC ports free, otherwise it refuses. The ADT must contain j274, and every address must equal the recorded J274 values; any mismatch refuses before any proxy call.
  2. Calls `p.pcie_init()` and checks that root port 0 is Apple vendor, type-1 header and READY.
  3. Starts the SMC with the proxyclient `SMCClient` on endpoint 0x20 and reads the `gP0d` key info. It refuses unless that is a 4-byte key, then writes `0x800001`.
  4. Brings up port 0 only, in the same order as UEFI: APPCLK, PERST# GPIO 0x98 low, PHY REFCLK0/1 request and ack, REFCLK enable, Tperst wait, PERST_OFF, GPIO high, wait perst-to-config, READY, then LTSSM start.
  5. If the link comes up, sets root port 0 bus numbers to 0/1/1 and reads 1:0.0 and 1:0.1: IDs, class, header, subsystem, PCIe DevCtl (No Snoop / Relaxed Ordering), link speed and width. It sizes the BARs and restores them, only if memory/IO decode is off and no exception was taken. Config access runs under the m1n1 exception guard (SKIP|SILENT), and exceptions are counted.
  6. **Always, in `finally`:** restores the root bus register, asserts PERST#, clears PORT_PERST_OFF, writes `gP0d` = `0x800000`, quiesces the SMC (`stop()`), checks the link went down, and compares a read-only snapshot of port 1 (FL1100) taken before and after.
  - Every MMIO write goes through an exact-address allowlist: 4 port-0 registers, 2 PHY registers, the PERST# GPIO, the root-port-0 bus register, and 12 bus-1 BAR registers. Port 1 and bus 2/3 writes are blocked.
  - Each phase has a SIGALRM time limit. Results go to `run-<ts>/result.json`.
  - Exit codes: 0 PASS_IDS, 1 LINK_DOWN / ID_MISMATCH / NO_CONFIG_RESPONSE, 2 error (power-down confirmed), 3 refused, 4 power-down not confirmed (power-cycle the mini).

**FACT (file:line)**
- SMC: `pcie_enable_devices.py:13-18` writes `gP0d` `0x800001` and then calls `smc.stop()`; `experiments/smc.py:28` gives `0x800000` as the off value; C precedent `m1n1-usb-s232/src/dcp.c:50-53`. Python `stop()` (`fw/asc/__init__.py:108`) matches C `rtkit_quiesce` (`smc.c:117`, `rtkit.c:659-710`).
- m1n1 `pcie_init` (`pcie.c:592`) only clears the port reset register. It never starts LTSSM and never touches the per-port PHY refclk on T8103. Port bring-up is copied from UEFI `AppleSiliconPciPlatformDxe.c:182-330`.
- Addresses, all confirmed in the recorded ADT dump: ECAM 0x690000000, RC 0x680000000, port0 0x681000000, port0 PHY 0x680084000, port1 0x682000000, GPIO 0x23c100000 (phandle 106), SMC 0x23e400000. PERST# is GPIO 0x98 for port 0 and 0x99 for port 1. ADT timings: `t-refclk-to-perst` = 100 µs, `perst-to-config` = 100 ms.

**HYPOTHESIS / open questions**
1. It is not verified that `0x800001` on `gP0d` alone powers the chip, or that the link then trains without CLKREQ (GPIO 150) or the ADT `manual-enable`.
2. SMC pin readback is not implemented because I could not confirm the rw command format. Success is judged by whether the PCIe link comes up.
3. It is assumed that bus-1 config routing needs the root port's secondary bus number set; the script sets it and restores it afterwards.
4. It is not known whether reading a non-present bus-1 device raises an SError. The probe only reads after link-up and under the exception guard.
5. PERST# GPIO handling differs from UEFI: UEFI writes only the mode/data value and clears the other bits (`AppleEmbeddedGpioControllerDxe.c:76`), while this script keeps the other bits. The original value is recorded.
6. The 100 ms settle time after power-on is a guess (`--power-settle-ms`).
7. Not tested here: whether UEFI shifts the FL1100 BAR 0x6C0000000 when Wi-Fi is powered before UEFI. This script powers Wi-Fi off before it exits. The BAR sizes it records are the input for that later test.
8. The README says to power-cycle the mini after a run, because mixing this with a chainload or launcher in the same boot is untested.

  - .venv-hv: 27 OK
- The proxy APIs it uses exist: proxy.py:802-805 (exc guard and count), proxy.py:1189 (pcie_init), fw/smc.py:84/134/162 and fw/asc/__init__.py:108.
- The SError guard claim holds. exception.c:479 reboots only when the guard is OFF; otherwise it counts the exception and returns.

**Defects**
1. wifi_probe.py:496-505. The power-down steps are chained inside one try block. If the PERST# GPIO rmw raises (for example after a serial desync), the `gP0d`=0x800000 write and smc.stop() are never attempted. Fix: wrap each step (PERST#, PERST_OFF clear, SMC off, SMC stop, link check) in its own try/except, and record per-step errors.
2. wifi_probe.py:516-517. `confirmed` ignores `link_down_after` and `port1_unchanged`. A link that stays up, or a changed FL1100 snapshot, still gives exit 0. Fix: require `link_down_after is not False`. Report a changed port 1 as a separate non-zero exit or warning.
3. wifi_probe.py:350 with m1n1 pcie.c:591-592. On T8103, m1n1 `pcie_init` already sets PORT_RESET (0x814) to RESET_DIS. That is the same bit as PERST_OFF, so the probe's "PERST_OFF" step does nothing. The controller-side reset is never asserted around REFCLK setup. The report's description ("only clears the port reset register") is backwards. Fix: clear port0+0x814 bit0 right after asserting the GPIO (line 336), so the order truly matches UEFI. The address is already allowlisted. Whether this affects link training is a hypothesis.
4. wifi_probe.py:10-11 and README §1. The claim "same mechanism as pcie_enable_devices.py" is incomplete. That script (lines 15-16) also writes `gP1a`=1, and the probe omits it. Fix: list `gP1a` as an open hypothesis in the README; do not write it in milestone 1.
5. wifi_probe.py:637-638. mkdir(exist_ok=False) runs after the hardware sequence. A same-second name collision raises and loses result.json. Fix: use exist_ok=True with a suffix, or tempfile.mkdtemp.
6. wifi_probe.py:305. The SMC key check looks only at length 4, not the type. Fix: also require info[1] in ('ui32', 'hex_'), or log and refuse on anything else.
7. README §5 says exit 2 means "끄기 확인됨" ("power-off confirmed"). But wifi_probe.py:628-630 also returns 2 when proxy connect fails, where power-down never applied. Fix: give connect failure its own code, or note it in the table.

**Claims checked**
- The `gP0d`/0x800001 values, the 0x800000 off value (smc.py:28) and the ADT addresses are consistent with the cited files. I did not re-dump the ADT; the .venv test passes against the recorded dump.
- "pcie.c:592" points at the set32 RESET_DIS line, not at pcie_init itself (line 725). pcie_init also applies tunables and DBI link speed/width, and polls LINKSTS BUSY (lines 560-680).

**Harm to the Mac mini and macOS (assessment)**
- No NVMe/ANS calls.
- The write allowlist is enforced and tested (test_guarded_mmio_blocks_port1).
- The worst realistic failure is a desynced proxy that leaves Wi-Fi powered or the SMC un-quiesced. The README already says to power-cycle. It should also say to pull mains power if the power button does not respond, because SMC is quiesced (hypothesis).
- No path writes storage or the macOS partitions.
