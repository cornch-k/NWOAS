ANALYSIS FINDINGS (FACT unless marked)
1. Their GPU hypervisor code is one guest-trapped page at IPA 0x300000000 (hv_agx_power_mmio.c:685) with sub-windows for: power (pmgr by ADT path /arm-io/gfx-asc and /arm-io/sgx, hv_agx_power_platform.c:16-37), local-reserve receipt, pool window, hwdata receipt, firmware-IO manifest, retained-root UAT broker, GPUVA v5 page-table broker, config snapshot and scanout. It also hooks the 16 KiB gpu-region (hv_agx_power_mmio.c:644).
2. Board and firmware gates: hv_agx_retained_platform.c:454 refuses anything except chip 0x8103 with board 0x26. :457 only sets profile validity, which needs OS firmware V13_5 and the J313 hwdata inputs. hv_agx_config_snapshot.c:17-22,47-52 hard-codes J313 values (perf states, gpu-region base 0x9fffb8000).
3. Their code depends on core-HV pieces that our tree does not have: the J313 launch contract and layout (hv_launch_j313_capture_base, J313_AUTONOMOUS_LAYOUT), hv_window_* in their hv_vm.c, their DCP scanout stack, hv_exc_bhl_wait_ticks, and spin_try_lock. Stage-2 format is the same in both trees (16K granule, same VADDR_* layout).
4. Interrupts: our HV delivers every AIC IRQ identity-mapped (vINTID == hwirq, our hv_exc.c ~2238) with mask-on-deliver / unmask-on-EOI. No route table is needed, but the J274 AGX0 ACPI device would have to use 563-566 and 575-579, not their 880-888. Their KMD also hard-codes the J313 GPU base (shared/src/apple_agx_uat_publication.c:58,100).
5. The GPU has no DART. It uses the UAT, whose root the HV protects through the gpu-region hook.
6. VMID: our hv_vm.c:276 writes VTTBR_EL2 with the bare table address, so VMID is 0. Our HV runs VHE, so a TLBI from the HV targets the guest's VMID. The idea that VMID 0 causes their GPU translation-cache slowdown is still the author's HYPOTHESIS.
7. Binary size and layout risk: the .bin includes .bss (s233: _file_end 0xd8000, bin 0x210000), and the payload sits at _end. Their static gpuva_v5 struct is about 9-10 MB (built-in backing tables). A static port would grow the bin well past 2162688 and move the payload/heap. Any port should allocate it at runtime, and only after the gates pass.
8. J274 13.5 log (appark-chainload-1558.log:108-109) shows gpu-region at 0xbfffb8000 and handoff at 0xbfff70000. HYPOTHESIS that these are the J313 equivalents at the top of 16 GB.

DEFECTS
